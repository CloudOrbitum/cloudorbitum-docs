Every page has one `content_type`. Using the same set of types everywhere means readers always know what kind of page they're on.

| Type | The reader wants to… | Example |
| --- | --- | --- |
| `overview` | Know what a product is and where to start | [Agents](/agents/) |
| `get-started` | Get a first result, fast | [Quickstart](/get-started/quickstart/) |
| `concept` | Understand how something works | [Concepts](/get-started/concepts/) |
| `how-to` | Do one task, step by step | [Connect Azure](/connect/azure/) |
| `tutorial` | Build something end to end | |
| `reference` | Look up exact values | [Limits and pricing](/reference/limits-and-pricing/) |
| `configuration` | Set an option | |
| `troubleshooting` | Fix a problem | |
| `faq` | Find a quick answer | |
| `example` | Copy working code | |
| `integration-guide` | Connect Orbitum to another tool | |
| `learning-unit` | Follow a guided path | [Learning paths](/learning-paths/) |
| `reference-architecture` | See how the parts fit together | [Reference architecture](/reference-architecture/) |
| `design-guide` | Make design decisions | |
| `navigation` | Choose where to go next | [Directory](/directory/) |
| `changelog` | See what changed | [Changelog](/changelog/) |

## Shapes

- **How-to:** prerequisites, then numbered steps with `<Steps>`, then how to check it worked.
- **Concept:** what it is, why it matters, how it works. No steps.
- **Reference:** tables and exact values. Little prose.
- **Troubleshooting:** the error message as the heading, then the cause, then the fix.
